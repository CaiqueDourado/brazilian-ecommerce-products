# Data dictionary: Brazilian e-commerce product catalog

[Leia em português](data-dictionary.pt-BR.md)

General rule: no bad value is deleted. When a value is corrected, the original stays in a `*_raw` column and the reason in a `*_flag` column. The only deletion is 224 customer-service rows of brands that asked for removal.

Period: offers were collected in 2019 (14.7M), 2020 (92.6M) and 2024 (7.3M), by my own crawlers and by affiliate feeds.

Flag values are in Portuguese (`reparado` = repaired, `disponivel` = available); their meaning is given below.

---

## plataformas.parquet (13 rows): platforms

| Column | Type | Description |
|---|---|---|
| id | int | Platform id |
| name | text | Name: Moovin, xTech, NuvemShop, Vtex, EzCommerce/Lynx, CiaShop, Magento, Shopify, Awin/Zanox, Magazine Luiza / BazaarVoice, AdMatic, Mercado Shops, Jet Commerce |

Note: "Awin/Zanox" and "Magazine Luiza / BazaarVoice" are not store platforms. They are data sources (an affiliate network and a reviews API). They are kept as they were and explained here.

## lojas.parquet (17,899 rows): stores

Stores registered in the project. Only 7,179 have offers in the catalog; the others were registered and never crawled, or returned no products.

| Column | Type | Description |
|---|---|---|
| id | int | Store id (the offers' `store_id`) |
| name | text | Store name, with mojibake and HTML entities repaired |
| name_flag | text | `ok`; `reparado` (609, repaired: "Tubar&#227;o Center" → "Tubarão Center"); `caractere_perdido` (151, character lost: the "�" was already stored at collection and cannot be recovered) |
| name_raw | text | Name as stored in the database |
| url | text | Store domain |
| slug | text | Slug rebuilt from the name, without the old bugs (`²` deleting the digit `2`, a trailing number incremented on collisions) |
| slug_raw | text | Old slug, used in the sites' URLs |
| active | bool | Store active in the project. Stores were deactivated at their own request (e.g. 7 stores at once in `reexporta_produtos.sql`), because the site was offline or "under maintenance", or case by case |
| created_at | timestamp | Date the store was registered in the project |
| platform_id | int | Most frequent platform among the store's feeds (→ plataformas.id); empty when the store had no feed |

## caracteristicas.parquet (3,102 rows): spec keys

Spec-sheet keys that were given a question-style title for the sites.

| Column | Type | Description |
|---|---|---|
| id | int | Id |
| key | text | Key as it appears in the spec sheet ("Tipo de CD/DVD") |
| question | text | Question used on the pages ("Qual o tipo de CD/DVD?"), generated by rule (`seta_titulos_caracteriscias_em_forma_de_pergunta.sql`) |

## grupos.parquet (18,328,454 rows): product groups

The same item sold by different stores, linked by the two-hop matching over 11 text and code keys plus the image signature (see [methodology](methodology.md)).

| Column | Type | Description |
|---|---|---|
| id | int | Group id (the offers' `group_id`) |
| short_name | text | Shortest name among offers with an image, preferring offers with a price. Computed when the group was created or reactivated; not recomputed when offers leave |
| long_name | text | Longest name among the offers (same moment) |
| created_at | timestamp | Group creation |
| last_change | timestamp | Last time an offer in the group got a new price or changed |
| last_change_is_bulk_date | bool | `true` when `last_change` = 2022-04-04 00:03:14.763, a date written in bulk to ~437k groups (not the real date) |
| active | bool | The group has at least one offer with a downloaded image. Price is not considered |
| offers | int | Number of offers in the group |
| stores | int | Number of distinct stores |
| brands | int | Number of distinct brands (normalized brand text) |
| group_flag | text | `ok`; `grande_demais` (too big: 3,107 groups with more than 1,000 offers, chained by regrouping); `muitas_marcas` (many brands: 11,743 with more than 10 brands); `sem_ofertas` (no offers: 14,999) |

## produtos/ (114,640,012 rows): offers

One row per collected offer (a product in a store).

| Column | Type | Description |
|---|---|---|
| id | int | Offer id. Ids jump by +39,517,486 at the December 2019 migration |
| store_id | int | Store (→ lojas.id) |
| collected_at | timestamp | First time the offer was collected |
| name | text | Product name, with mojibake repaired. Already normalized at the source (capitalization, spaces) |
| name_flag | text | `ok`; `reparado` (519,564); `caractere_perdido` (978) |
| name_raw | text | Name as stored in the database |
| url | text | Offer URL in the store at collection time |
| brand | text | Brand given by the store or feed. Normalized at the source: symbol-only brands blanked, long brands cut at 30 characters |
| availability_raw | text | Availability as received (13 spellings) |
| availability | text | `disponivel` (available), `indisponivel` (unavailable) or empty (85% of offers) |
| availability_reliable | bool | `false` for stores 1, 2 and 3 (Submarino, Americanas, Shoptime), where one crawl path stored "out of stock" as "in stock". Confirmed in the B2W crawler code; other stores were not checked, so read the field with care for any store |
| price_raw | decimal | Price as stored in the database |
| price | decimal | Price in BRL; empty when `price_flag` ≠ `ok`. Sale price when there was one, otherwise the regular price. Part of the Americanas and Shoptime offers got the Submarino price |
| price_flag | text | `ok`; `zero` (28.1M); `inativo_99999` (1.5M: the crawler wrote 99,999.99 for inactive products) |
| group_id | int | Product group (→ grupos.id). Empty for 7.4M offers, partly because loading downloaded images cleared the group |
| group_rule | text | Rule that put the offer in its current group (after regrouping): `EAN longo` (long EAN), `productName`, `productName_fingerprint`, `productName_metaphone`, `productName_ngram`, `productName_tokenizada_fingerprint`, `productUrl`, `productImage_hash_Imagio_ComputeHash`, `EAN curto + Brand` (short EAN + brand, and variants) The same rules, with the fingerprint fixed and an attribute check, are implemented in [DedupKit](https://github.com/CaiqueDourado/DedupKit) (`LEGACY_RULES` reproduces them). |
| group_rule_original | text | Rule of the first, most conservative match. Empty when an ungrouping script erased it |
| image_hash | text | Image signature: the photo shrunk to 16×16 grayscale and hashed with SHA-256. The same image (same pixels after shrinking) has the same signature; because the hash is exact, a photo the store resized or recompressed usually gets a different signature. Format: the 32 bytes written in decimal and concatenated (80–84 characters), as stored in the database. Kept as is: there is no safe conversion to hex, and it works the same for comparing images. To hash new images, see [SimilarImageFinder](https://github.com/CaiqueDourado/SimilarImageFinder); it hashes decoded pixels, so it does not reproduce these values |
| image_width / image_height | int | Size of the image **after** optimization. May belong to another image because of a race condition in the downloader. Use with care |
| image_is_generic | bool | `true` when the same signature appears on more than 100 products ("no photo" images, store logos). These images do not count for matching |

## ficha/ (31,904,957 rows): spec sheet

One row per key/value of a product.

| Column | Type | Description |
|---|---|---|
| id | int | Row id |
| product_id | int | Offer (→ produtos.id) |
| position | int | Order of the attribute on the product page |
| key | text | Attribute name (4,370 distinct keys; some had their spelling normalized at the source) |
| value | text | Value; empty when it was `''`, `Null`, `-` etc. |
| value_raw | text | Value as stored in the database |

## eans/ (32,119,395 rows): product identifiers

One row per code.

| Column | Type | Description |
|---|---|---|
| id | int | Source row in the database (repeats when the value held several comma-separated codes) |
| product_id | int | Offer (→ produtos.id) |
| code_index | int | Position of the code inside the original value (1, 2…) |
| code | text | Code, without spaces |
| value_raw | text | Value as stored in the database |
| ignored_in_grouping | bool | Code blacklisted for matching: generic (repeated in more than 5 products of the same store), letters only, truncated, more than 15 different names, starting with 000, "SEM GTIN". Empty in 10.4M newer rows |
| code_type | text | `gtin_valido` (valid GTIN, 79%: check digit verified); `gtin_digito_errado` (wrong check digit); `numero_curto` (short number); `numero_outro_tamanho` (other length, includes 8-digit NCM codes); `codigo_alfanumerico` (store SKU); `notacao_cientifica` (broken by Excel, e.g. `90E+12`); `texto` (text); `vazio` (empty) |
| source_key | text | Spec-sheet key holding the same code for the same product ("Código de Barras", "Isbn"…). The crawler never filled the original source column, so the source is recovered from the spec sheet |

## categorias/ (220,060,122 rows): categories

Pieces of each offer's category path (breadcrumb).

| Column | Type | Description |
|---|---|---|
| id | int | Row id |
| product_id | int | Offer (→ produtos.id) |
| level | int | Position of the piece after splitting the text on `>`, `\|`, ` - `, `,` and `/`. Not the depth of the store's taxonomy |
| category | text | Category text. In rows cleaned in 2020, accents, capitalization and plural are already standardized ("Automotivos", "Femininos"); in the others, as the store wrote it |
| category_normalized | text | Category merged by phonetic and fingerprint keys (the "hard" 2020 normalization); empty for later crawls |
| category_origin | text | `limpa_2020` (cleaned in 2020, 86%) or `original` |
| category_flag | text | `ok`; `nivel_alto` (level above 10: SEO tag lists of VTEX stores); `codigo_ou_ruido` (internal codes such as `Coll-…`, `SkuOriginal-…`, numbers only, "No Magalu"); `curta_demais` (too short) |

Known losses at the source are in [data-quality.md](data-quality.md): every category containing a digit was deleted in 2020 (e.g. "Galaxy J5"), and the feeds' third category was never stored.
